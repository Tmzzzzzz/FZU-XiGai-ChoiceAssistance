# 出题顺序算法

面向考前短期突击：**在有限时间里让“下一题”尽量值钱**。整套规则只看作答记录本身，不读系统时间、不安排“几天后复习”，因此关掉程序隔多久再打开，顺序逻辑都一致。

## 一、每题记录什么

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `attempts` | 累计作答次数 | 掌握度的置信度 |
| `right` / `wrong` | 累计对 / 错次数 | 错误压力、基础正确率 |
| `streak` | 当前连续答对次数 | 掌握度的加分项 |
| `recent` | 最近 5 次结果，如 `"10110"` | 最近正确率 |
| `correct` | 最近一次是否答对 | 错误压力的即时加成 |
| `chosen` / `at` | 选项与时间戳 | 仅用于回看，不参与排序 |

## 二、五个评分维度

优先级满分 1.0：

```
优先级 = 0.40·未掌握度 + 0.25·错误压力 + 0.15·难度适配 + 0.12·覆盖缺口 + 0.08·考点频次
```

### 1. 未掌握度（权重 0.40，主导项）

```
掌握度 m = 0.5·(1-c) + c·(0.55·最近正确率 + 0.30·总正确率 + 0.10·连续答对系数)
c = min(attempts/4, 1)          # 作答次数越多，越相信自己算出来的值
未掌握度 = 1 - m                # 没做过的题固定取 0.75
```

- **向 0.5 收缩**：只答对一次不等于会，`c=0.25` 时掌握度约 0.60；答对 4 次才接近 0.90。
- **最近正确率占大头**：同样 3 次对 2 次，“对-错-对”比“对-对-错”更让人放心。
- **新题给 0.75 而不是 1.0**：完全没见过的题价值高，但不如“确定不会”的题紧迫，避免整轮被新题淹没。

### 2. 错误压力（权重 0.25）

```
错误压力 = 0.6·min(wrong/3, 1) + 0.4·(wrong/attempts)
最近一次答错再 +0.15（上限 1.0）
```

- 用 `min(wrong/3,1)` 做**边际递减**：错 3 次就到顶，错 10 次不会继续叠加，防止一道题永久霸屏。
- 叠加错误率，区分“只做过一次就错”和“做了五次错三次”。
- 最近一次答错额外加权，符合“刚错过的题印象最浅、最该马上补”的直觉。

### 3. 难度适配（权重 0.15）

难度先验由题目属性估算，不依赖作答数据：

```
难度 = 0.30（单选）/ 0.46（多选）
      + 0.05（五个选项）+ 0.04（题干长度系数）
      + 0.05 × max(0, 正确项个数-2)（多选）
适配 = 1 - |难度 - 0.60| / 0.60     # 越接近 0.60 越优先
```

考前突击的性价比曲线是钟形的：太简单的题做了也不涨分，太难的题短期啃不动，**中等偏难**收益最高。新题不参与这一项（固定 0.5），否则一上来会被难题占满。

### 4. 覆盖缺口（权重 0.12）

```
整个知识点一道没做过 → 1.0
知识点练过、但这道题没做过 → 0.6
做过 → 0.0
```

配合下面的“同类惩罚”，让队列横向铺开：先把没碰过的知识点过一遍，再回头深挖。

### 5. 考点频次（权重 0.08）

用**题库内该知识点的题量**作代理：题多的知识点更可能是重点章节，命中概率更高。

```
频次 = 该知识点题数 / 全库最大知识点题数
```

这是唯一一个“猜测性”指标，所以权重压到最低；将来若拿到真题分布，只需替换这一项。

## 三、排序过程

不是简单排序后一刀切，而是**贪心逐位选**：

```
while 还有候选:
    对每道候选计算：基础分 + U(0, 0.05) 抖动
    减去同类惩罚：
        与上一题同知识点      -0.22
        最近三题出现过该知识点 -0.10
        与上一题同章节        -0.08
    取最高分者放入队列
```

- **为什么要惩罚**：连出三道“总体国家安全观”会让人疲劳，也不利于横向覆盖；惩罚值 0.22 大于“错误压力”的最大差距（0.25）的一半，足以让位，但压不过“薄弱 vs 已掌握”的差距（0.40）。
- **为什么要抖动**：同分题（大量新题分数完全相同）每次都按同一顺序出会很机械；0.05 的抖动让每轮略有差异，但不足以颠倒明显的高低分——实测同一批数据两次构建，前 10 题集合高度重合，只是次序不同。
- **复杂度**：271 题约 19 ms，可忽略。

## 四、边界情况

| 情况 | 行为 |
| --- | --- |
| 全新用户（零记录） | 所有题 `need=0.75`、错误压力 0，顺序由覆盖缺口 + 频次 + 难度适配决定，同类惩罚保证横向铺开 |
| 全部题都已掌握 | `need` 接近 0，仍按频次/覆盖/抖动给出稳定顺序，不会空队列 |
| 候选只有 1 题 | 直接返回，不做无意义的惩罚计算 |
| 筛选后只剩少量题（<5） | 惩罚仍然生效，但可能不得不连续同类；不会报错、不会死循环 |
| 所有候选同属一个知识点 | 惩罚无法避免，退化为按 `need`/`pressure` 排序 |
| 某题连错 10 次 | 错误压力饱和在 1.0，仍只是 0.25 的权重；答对两次后 `need` 下降，自然让位 |
| 记录缺字段 / 旧版本数据 | 载入时补齐 `wrong/right/streak/recent`，缺失的 `recent` 用最近一次结果推导 |
| 记录文件损坏 | 按空白进度启动（既有逻辑），不阻塞出题 |
| 错题本模式 | 候选集就是错题集合，用同一套评分排序，`need` + `pressure` 自然主导 |
| 题型范围（单选/多选） | 先按题型过滤再排序，规则不变 |

## 五、为什么不用时间间隔

原来的实现是“答错 6 小时后重练、连对按 1/3/7/16/35 天拉开”。它适合长期记忆，但对考前突击有三个问题：

1. **无法在一天内生效**：考前只有几小时，间隔表只能安排到明天以后。
2. **状态依赖挂钟**：调系统时间、隔夜再开，顺序就变，行为不可预测。
3. **忽略了“这道题值不值得现在做”**：时间到了不等于该做，时间没到也不等于不该做。

新模型把“该不该现在做”交给掌握度、错误频率和提分性价比来判断，时间只作为记录字段保留。
